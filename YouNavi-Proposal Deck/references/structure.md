# 结构框架

用户确认标题/大纲后、生成 slide 前读取本文档。本文档负责把内容映射到 YouNavi 产品风 deck 的视觉框架。

## Deck 主脊柱

YouNavi 产品风 deck 通常沿着这条叙事脊柱展开：

| 页面角色 | 目的 | 推荐版式 |
|---|---|---|
| 封面 | 命名主题，建立产品气质 | `封面` |
| 背景 | 说明为什么现在要讲这件事 | `Section Divider` 或 `Point Rows` |
| 痛点 | 展示具体用户或流程阻力 | `Point Rows` |
| 核心判断 | 用一句话说清 thesis | `Section Divider`，必要时可用 `slide--ink` |
| 系统解法 | 解释产品/系统如何回应问题 | `Text Plus Screenshot` 或 `Card Grid` |
| 工作流 | 展示一步步怎么发生 | `Point Rows` 或流程卡片 |
| 证据 | 展示数字、结果或案例 | `指标` |
| 对比 | 讲清 before/after 或不同方案 | 用户确认后用表格，否则用 rows/cards |
| 路线图 | 说明下一步怎么推进 | `Card Grid` 或 rows |
| 系统架构 | 说明输入、处理、输出或模块关系 | `系统架构` |
| 收尾 | 给出最终主张和下一步行动 | `收尾` |

只使用需要的页面角色。短 deck 不要硬塞完整十页。

## 页数映射

| 用户要求 | 推荐结构 |
|---|---|
| 5 页 | 封面、问题、解法、证据、收尾 |
| 6-8 页 | 封面、背景、痛点、核心判断、解法、工作流/证据、下一步、收尾 |
| 9-12 页 | 使用完整主脊柱，可重复 1-2 个内容角色 |
| 13 页以上 | 增加章节和内容页，不要增加更多 hero 页 |

## 按页面角色选择视觉系统

## 四周小标注策略

四周小标注包括顶部 chrome、品牌点、右上角页面标签、页脚左侧 deck/团队信息、日期年份和页码。

- 如果用户提供了品牌、团队、年份或 Deck 名称，按用户信息填写。
- 如果用户没提供，生成前必须询问：使用占位符，还是删除这些非必要标注。
- 选择占位符时，使用 `[品牌名]`、`[作者 / 团队]`、`[Deck 名称]`、`[日期]`、`[年份]`。
- 选择删除时，可移除品牌名、团队名、日期、Deck 名称等可见文本；但保留页码、进度条、底部圆点导航等功能性元素。
- 不要自行编造团队名、年份、作者、网址或品牌标识。

### Hero 页

包括封面、核心判断、章节页和收尾页。

- 使用 `slide--brand`、`slide--ink` 或非常稀疏的 `slide--canvas`。
- 一页只讲一个想法。
- 可以使用更大的标题字号。
- 短标题使用默认封面；标题超过 18 个中文字符、包含长英文短语，或会超过 3 行时，必须使用 `封面（长标题）`。
- 标题区域要有约束，但不能窄到只占半张页面；长标题用 `stage--cover-long`、`display--long`、`cover-title--long`。
- 封面和收尾页脚可使用 `[作者 / 团队] · [品牌名]`；如果用户选择不要四周标注，则删除该文本，只保留必要页码。

### 内容页

包括背景、痛点、工作流、解释、路线图。

- 使用 `slide--canvas` 或 `slide--surface`。
- 优先用 rows、cards 或双栏截图布局。
- 先放页面标题，再放结构化内容。
- 正文要短；每个 row/card 最好只有一句解释。
- 普通页脚默认使用 `[Deck 名称]` 和页码；如果用户选择不要四周标注，则只保留页码或极简 folio。

### 证据页

包括指标、案例、采用情况、结果。

- 2-3 个核心数字用 `指标` 版式。
- 一页只用一个 `.em` 高亮最重要数字。
- 用短 label 解释数字，不写长段落。
- 如果数字需要解释，另起一页 rows/cards。

### 产品演示页

包括截图、功能 walkthrough、before/after 状态。

- 使用 `Text Plus Screenshot`。
- App UI 截图优先用 16:10 框。
- 文案侧包含 chip、标题和一句短说明。
- 除非是对比状态，不要在一页里塞多个截图。

### 表格页

表格必须经过 `SKILL.md` 第五步确认后才能使用。

适合表格的内容：

- 功能对比
- before/after 映射
- 按阶段的路线图
- 价格/套餐对比
- 责任分工矩阵
- 按分组展开的结构化指标

不适合表格的内容：

- 情绪化叙事
- 三个简单要点
- 产品截图展示
- 能用 rows/cards 更清楚表达的内容

### 系统 / 工作流页

适合解释产品怎样把输入变成结果，或团队怎样协同。

- 顺序关系用 `工作流步骤`。
- 模块关系用 `系统架构`。
- 不要画复杂技术拓扑；面向产品叙事时，读者只需要理解“输入是什么、系统做什么、用户拿到什么”。
- 如果模块超过 4 个，拆成两页，不要把架构图压小。

## 大纲草拟规则

当用户只给标题或主题时，默认提出：

- 6-8 页版本。
- 每页一句目的。
- 是否可能需要表格的判断。
- 明确询问用户是否认可。

示例：

```text
我先拟一个 7 页版本：
1. 封面：[主题]
2. 背景：为什么现在需要讲这件事
3. 痛点：当前流程的三个断点
4. 核心判断：一句话 thesis
5. 方案：产品/系统如何承接
6. 证明：指标或案例
7. 收尾：下一步行动

我判断这里暂时不需要表格。这个方向可以吗？如果你有自己的大纲，也可以直接发我。
```

## 信息密度规则

- 一页只承载一个决策、一个论点或一组证据。
- rows/cards/metrics 默认数量是 3。
- 双栏布局只在第二栏是截图、图示或对比时使用。
- 只有 label 很短时才用 4 张卡片。
- 一页不要放 5 个以上等权卡片；除非是路线图或矩阵，并且已检查可读性。
