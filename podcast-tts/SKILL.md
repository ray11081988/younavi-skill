# Podcast TTS Generator

使用 ListenHub TTS API 将播客脚本转换为多角色音频，并自动合并成完整播客文件。

## 功能

- 解析带角色标记的播客脚本（支持 `【角色名】` 格式）
- 自动分段处理长文本（避免 API 单次调用限制）
- 支持多角色音色配置
- 批量生成音频片段
- 自动按顺序合并为完整 MP3
- 完整的错误处理和重试机制

## 使用方法

用户提供：
1. 播客脚本 TXT 文件路径
2. 角色到音色的映射关系（例如："旁白用原野，主持人用晓曼"）

Skill 会：
1. 获取 ListenHub 中文音色列表
2. 根据用户指定匹配音色 ID
3. 解析脚本按角色分段
4. 调用 API 生成所有音频片段
5. 使用 ffmpeg 合并为完整播客
6. 打开输出文件夹供用户查看

## 输入格式

### 脚本格式示例

```
【旁白】
欢迎收听 AI 智识录。今天为您带来的是...

【主持人】
首先，我非常荣幸向大家介绍...

【嘉宾】
谢谢大家。那是 2016 年的一个夏日...

【旁白】
好了，今天的分享就到这里...
```

### 角色标记规则

- 使用 `【角色名】` 标记角色切换
- 角色名可以是任意中文/英文（如：旁白、主持人、Jim Fan、嘉宾等）
- 标记独占一行
- 标记后的所有文本归属该角色，直到下一个角色标记

## 配置

### ListenHub API 配置

- **API Key**: 需要用户去https://listenhub.ai/zh/settings/api-keys 申请
- **API Endpoint**: `https://api.listenhub.ai/openapi/v1/tts`
- **音色列表**: `https://api.listenhub.ai/openapi/v1/speakers/list?language=zh`

## 技术细节

### 分段策略

- 单段最大字符数：1500 字
- 按句号/问号/感叹号切分
- 保持句子完整性

### API 调用

- 请求格式：`{"input": "文本", "voice": "音色ID"}`
- 响应格式：直接返回 `audio/mpeg` 二进制
- 速率限制：400 次/窗口
- 重试策略：最多 3 次，指数退避

### 音频合并

- 使用 ffmpeg concat demuxer
- 保持原始音质（32kHz / 128kbps / mono）
- 无需重新编码（`-c copy`）

**Skill 执行**：

2. 获取中文音色列表，匹配：
   - 原野 → CN-Man-Beijing-V2
   - 晓曼 → chat-girl-105-cn
   - 苏哲 → suzhe-45bbbe54
3. 解析脚本识别 4 个角色段落
4. 按 1500 字拆分为 9 个音频块

7. 打开输出文件夹

## 错误处理

- API 限流：自动等待并重试
- 网络错误：指数退避重试
- 音色不存在：提示可用音色列表
- 脚本格式错误：给出修正建议
- ffmpeg 未安装：提示安装命令

## 依赖

- Python 3.x（系统自带）
- ffmpeg（音频合并）
- 网络连接（API 调用）

## 注意事项

1. **API 配额**：注意 ListenHub 的速率限制和用量配额
2. **文件大小**：长播客会生成较大的 MP3 文件（约 1MB/分钟）
3. **音色一致性**：同一角色在整个播客中使用同一音色
4. **标记规范**：确保角色标记格式正确（`【】`中文方括号）
5. **文本长度**：单个角色段落过长会自动分段，合并时无缝衔接
