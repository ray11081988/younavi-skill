# 客户雷达

围绕 BD 的四个问题工作：客户是谁、为什么现在联系、应该找谁、如何触达。此 Skill 可独立运行；保持只读，不自动发送消息，不修改用户记忆或客户资料。

## 研究模式

开始时使用不产生数据查询费用的方式判断天眼查 CLI 是否存在、已配置且已登录。不要为了测试连接而执行收费查询。

- 标准模式：天眼查不可用、未登录、用户未同意可能的额度消耗，或本次不需要工商数据时使用。依靠内部原始资料、公司官网、政府与监管披露及可信媒体完成报告。
- 工商增强模式：用户已经连接自己的天眼查账号，并已明确同意或在产品设置中持续允许可能产生费用的查询时使用。只查询本次 BD 判断真正需要的工商信息。

无论哪种模式都必须完成可用报告。不得把安装天眼查作为使用本 Skill 的前置条件。

## 工作流程

### 1. 明确任务

确定目标公司、用户的业务目的和希望推动的下一步。优先从全局记忆、常用人名、历史会议和已有文件中补齐背景。

公司指代存在多个合理候选时先完成企业锚定；业务目的缺失但不影响基础调查时继续执行，在结果中标明需要用户补充。

### 2. 回顾内部客户上下文

查找用户与目标公司、相关人员和相邻机会的历史交流，提取：

- 已认识的人及真实关系；
- 对方明确表达过的目标、问题和时间点；
- 已承诺事项和当前进展；
- 用户能够提供的价值。

引用原话时必须来自实际看到的内容。不要把推测写成客户需求。

同一人物出现近似姓名时，回到原始资料确定规范名；无法确定时明确标记“姓名待确认”，不得用“姓名A/姓名B”合并输出。

### 3. 锚定企业

当用户提供简称、品牌名、曾用名或模糊公司名时：

- 工商增强模式可运行：

```bash
tyc company companies "<用户原始公司名>" --pageSize 10 --md
```

- 标准模式使用内部原始记录、公司官网、政府或监管公示锁定企业全称；无法唯一确定时向用户确认。

依据企业全名、经营状态、法定代表人、统一社会信用代码和用户上下文选择唯一主体。出现多个无法排除的候选时向用户确认，不自行挑选。主体已经精确且内部资料足够时不重复查询。

### 4. 获取企业基础画像

工商增强模式下，企业主体确认后可按需运行：

```bash
tyc company registration-info "<企业全名或统一社会信用代码>" --md
```

标准模式从公司官网、政府或监管公示获取能够确认的主体信息。只提取对本次 BD 判断有用的登记状态、企业属性、法定代表人和公开企业联系方式。工商登记身份不自动等于采购决策权；标准模式无法确认的字段标记“未经工商数据核验”，不得猜测。

### 5. 核实具体人员

只有内部资料或用户已经提供具体姓名，并且需要确认其商业角色时：

- 工商增强模式可运行：

```bash
tyc executive person-profile "<企业全名或企业 ID>" --humanName "<人员姓名>" --md
```

- 标准模式只使用内部原始资料、公司官网、企业正式公告或监管披露确认公开职务。

区分法定代表人、股东、董监高和其他任职角色。没有具体姓名时不要遍历全部人员，也不要根据同名结果强行认人。公开职务不能证明私人联系方式或实际采购权。

### 6. 寻找“为什么是现在”

必要时使用网页搜索补充近期融资、招聘、产品发布、市场扩张、合作、招投标或组织变化。优先使用公司官网、官方披露和可信媒体，列出实际采用的链接与日期。财务数字、组织变动和战略转型必须由公司官方披露或监管文件支持；聚合平台、自媒体和百科只能作为搜索线索，不能单独作为确定结论。

商业信号只能支持切入假设，不能证明对方已经存在某项需求。

### 7. 查找触达路径

直接从全局记忆、常用人名、历史会议和已有文件中寻找一至三跳的真实关系路径。若 `connection-radar` 已经可用，可将其作为消歧和多跳检索的增强；缺失时继续完成任务，不中断，也不要求用户安装。

保留全部真实中间人，并区分“提到过”“认识”“关系较强”和“愿意引荐”。天眼查中的任职、投资或股权关系不能当作私人引荐关系。

只有资料明确证明用户拥有某人的直接联系方式时，才推荐用户直接联系；否则保留实际掌握联系方式的中间人。

### 8. 形成 BD 行动建议

综合内部交流、企业信息和近期信号，判断：

- 是否值得现在跟进；
- 最应该接触的角色或已确认人员；
- 最可信的切入理由；
- 现在只需要完成的一个动作。

只有内部原话或明确的组织授权证据能够证明某人拥有最终拍板权时，才称其为“实际决策者”或“最终决策者”。否则使用“优先联系人”“核心推动者”或“可能参与决策的人”，并标明决策权尚未确认。

生成一段可以直接发送的话术。逐句检查其中关于客户需求、我方产品能力、Demo 状态、部署方式、价格、效果、数字和合作进展的陈述；每项都必须有内部资料明确支持。没有证据时不得换一个类似说法继续声称已经具备或完成，应改成询问、待确认事项或下一步提议。

## 调用边界

- 标准模式不调用天眼查。
- 工商增强模式默认最多调用三次天眼查：企业锚定、登记概览、具体人员画像各一次。
- 默认不调用风险、司法、知识产权、历史信息等专项工具；用户明确要求尽调或对应信息直接影响本次决策时再下钻。
- 不使用 `--output-file`，不把查询结果自动写入本地文件或全局记忆。
- 不自动安装、初始化、登录或授权天眼查，不使用开发者、其他用户或共享账号的凭据。
- 用户尚未知情同意可能的额度消耗时，不执行天眼查数据查询。
- 天眼查不可用时直接使用标准模式，不报错、不暂停任务，并明确哪些信息未经工商数据核验。
- 只使用公开企业联系方式，不输出或推测私人联系方式。

## 天眼查连接引导

仅在未连接会明显影响企业消歧、股权、高管或工商变更核验时，在完整报告末尾显示一次简短引导，不要反复推销：

> 本报告已用标准模式完成。当前未接入工商数据，相关企业主体、股权或高管信息尚未经过天眼查核验。如需增强核验，可接入天眼查 CLI；接入时请使用你自己的天眼查账号，查询可能消耗账号额度或产生费用。接入后可说“重新核验这家公司”。

用户主动要求连接时：

1. 优先引导使用 YouNavi 官方的工具或扩展安装入口，不编造安装命令；
2. CLI 已安装但未配置时，可提示运行 `tyc init`；
3. CLI 已配置但未登录时，可提示运行 `tyc login`；
4. 登录前说明必须使用用户自己的账号，并提示查询可能消耗额度或产生费用；
5. 连接成功后只重新执行缺失的工商核验，不重复整份内部与网页研究。
