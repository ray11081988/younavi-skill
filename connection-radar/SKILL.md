# 人脉雷达

利用 YouNavi 已有的私人上下文，帮助用户找回目标人物、理解现有关系并采取下一步行动。保持只读，不维护额外数据库；内部资料负责寻找线索和关系，公开网页只负责核实候选身份。

## 工作流程

### 1. 理解用户要找谁

提取用户记得的姓名、公司、职位、人物特征、出现时间、提及人和联系目的。

信息模糊时先从现有上下文查找。只有出现多个无法区分的人物时，才向用户追问一个最关键的问题。

### 2. 查找原始线索

按以下顺序查找：

1. 常用人名表；
2. 全局记忆；
3. 当前相关的录音、会议和历史对话；
4. YouNavi 的内部历史检索能力；存在 `recall_research` 时使用它。

优先找到目标最初被提到的录音或会议片段。说明是谁、在什么时间、什么场景下提到了这个人。

只复述资料明确支持的内容。引用原话时必须来自实际看到的原始内容；无法确认原文时使用普通摘要，不加引号。

### 3. 判断是否找到目标

如果姓名、公司或身份仍不确定，明确说“尚未确认”，不要选择一个看起来最像的人。

不要因为两个人都很有钱、在同一行业、出现在同一会议或名字相近，就认定为同一个人。不要把会议发言人与发言中提到的人混为一人。

### 4. 必要时核实公开身份

只有内部资料已经给出具体候选人，但姓名、公司或职位仍不完整，或者用户明确要求核实时，才执行网页搜索。内部资料已经足够回答时跳过。

使用至少两个稳定特征组合搜索，例如姓名加公司、职位或产品。优先采用公司官网、监管披露、官方工商信息和可信媒体；关键身份没有可靠来源支持时继续标记“尚未确认”，不要选择最像的搜索结果。

列出实际采用的网页标题和链接。公开网页只能补充公开身份，不能证明私人交情、认识关系或引荐意愿。

### 5. 查找关系路径

先检查用户是否能直接联系目标。没有直接关系时，再查找一至三跳的中间人。

区分以下关系：

- 提到过目标；
- 认识目标；
- 与目标关系较强；
- 愿意帮助引荐。

前一种关系不能自动证明后一种。

完整保留每一个真实中间节点。资料写明“Sam 的弟弟是目标的同学”时，路径必须写成：

> 用户 → Sam → Sam 的弟弟 → 目标人物

不得压缩成“Sam → 目标人物”。中间人姓名未知时，保留“Sam 的弟弟”等真实称谓。

每一跳都说明来源。没有证据的关系不作为确定路径推荐。

### 6. 给出最直接的行动

找到线索后，不停留在背景分析。直接告诉用户：

- 现在最应该联系谁；
- 联系他的目的是什么；
- 是先确认身份、确认双方是否认识，还是直接请求引荐；
- 用户接下来只需要做的一个动作。

生成一段可以直接发送的话术。只使用资料中已有的称呼和背景，不编造承诺、交情或业务进展。

关键关系不确定时，先询问情况，不直接要求引荐。

## 事实边界

- 只输出内部资料明确支持的事实。
- 找不到时明确说没有找到，不补全人物或关系。
- 同名或身份冲突时不强行合并。
- “某人说过”不代表该说法已经得到外部核实。
- 不用公开网页反推内部资料中没有出现的人脉关系。
- 不虚构原话、精确数字或成功率。
- 不自动修改全局记忆、常用人名表或历史资料。

## 输出格式

保持简洁，按以下顺序输出：

```markdown
## 结论

用一至两句话说明找到了什么、还缺什么，以及现在最应该联系谁。

## 找到的原始线索

- 来源：
- 时间：
- 谁提到的：
- 明确内容：

## 目标信息

- 姓名：已确认 / 可能是 / 未知
- 公司或职位：
- 尚未确认：

## 公开核实

- 仅在实际执行网页搜索时输出：
- 核实结果：
- 来源链接：

## 关系路径

用户 → 中间人 → 目标人物

- 每一跳的关系和来源：
- 这条路径能证明什么：
- 这条路径不能证明什么：

## 下一步

现在只需要做的一件事：

## 推荐话术

一段可以直接发送的话术。
```

没有可信关系路径时省略路径，不为了填满格式而生成内容。只找到信息源时，把“联系该信息源确认身份”作为下一步。
